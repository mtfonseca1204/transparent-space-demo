## Acceptance Bar

Demo parity is visible parity with Kraken: every customer-openable Kraken surface must exist under `/demo`, use deterministic synthetic fixtures, avoid visible real xStock symbols, and avoid live data calls outside auth/session/admin APIs.

The hard fake-data boundary remains synthetic `demo-*` pool keys plus `space=demo`. Stale Kraken pool keys, stale Demo preview keys, and persisted Kraken RFQ/token state must resolve to canonical Demo symbols/pools before dashboards render.
