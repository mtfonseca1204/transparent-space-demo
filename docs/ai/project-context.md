# transparent-space Project Context

Last verified: `2026-06-02`

## Purpose

`transparent-space` is the main frontend for the Transparent Space product. It is the operator-facing and user-facing Next.js application deployed on Vercel and backed by Solana, Worldchain, Gensyn, Perle, Katana, Monad, 0G AI, and Hyperliquid/HIP-3 data services.

## Important Code Paths

- `lib/solana-indexer-client.ts`
  - server-side Solana Railway client with retry and pagination helpers
- `app/xstocks/page.tsx`, `app/xstocks/earnings/page.tsx`, `components/xstocks/weekend-movers-builder.tsx`, `components/xstocks/earnings-builder.tsx`, `components/xstocks/template-nav.tsx`, `app/api/xstocks/logo/route.ts`, and `public/xstocks/brand/*`
  - Public xStocks Weekend Movers image-builder surface. It fetches `GET /api/public/xstocks/weekend-movers-template` server-side from the Solana indexer and passes the exact HTML-style globals (`MOVERS`, `WEEK_LABEL`, `POST_TIME`, `BRAND_ASSETS`) into a client renderer that preserves the standalone template's Ladder, Tape, Split, aspect, theme, data-column, and footer controls. PNG export uses `html-to-image`. Official xStocks horizontal lockups are vendored under `public/xstocks/brand/`; per-token row logos come from `MOVERS[].logo`, which the Solana indexer maps from Backed's public `type=xstocks` token metadata. Because `xstocks-metadata.backed.fi` returns no CORS headers, the row `<img>` elements load through the same-origin proxy `GET /api/xstocks/logo?t=<TICKER>` (`app/api/xstocks/logo/route.ts`), which validates the ticker against `^[A-Za-z0-9.]{1,10}x$`, fetches `https://xstocks-metadata.backed.fi/logos/tokens/<TICKER>.png` server-side, and re-emits it with a 1-day cache. This keeps `crossOrigin="anonymous"` working so `html-to-image` can render the canvas without tainting it. The builder additionally pre-fetches every proxy URL on mount, converts each PNG to a `data:` URL via `FileReader.readAsDataURL`, and serves those through `LogoDataUrlContext` so `<TokenLogo>` renders inline images. This sidesteps a known `html-to-image` race where the library re-fetches each `<img>` during canvas serialization and can end up giving multiple `<img>` elements the same bytes (visible symptom: all five row logos exported as the LLY logo). `Download PNG` and `Post on X` are disabled with a `Loading logos` label until the pre-fetch resolves. The Ladder variant now also has an editorial "Why" column (toggleable, off by default) that reads from a `WHY_OVERRIDES` map hardcoded at the top of `weekend-movers-builder.tsx` keyed by ticker, falling back to `MOVERS[].narr` if the indexer ever populates it. The whys are hand-written per week alongside the weekly post; update the map when new tickers enter the top 10. Tape and Split variants accept but ignore the new `showWhy` prop. The Ladder also renders a `Company name` line under each ticker (toggleable, on by default) sourced from a parallel `COMPANY_META` hardcoded map (e.g. `HOODx -> "Robinhood"`); update this map when new tickers appear. Row visual anatomy follows the v2 spec: chunky 74/56/44 px circular logo chip (white disc, 1.5px ring via `box-shadow`, soft drop shadow), ticker at 44/32/24 px, delta at 52/40/30 px, rounded left-anchored gradient bar (width = `|dPct| / maxAbs`) in a `--track` rounded background (`#242a29` ink / `#eef0ef` paper), and both Friday/Sunday prices anchored above the bar (gray left, white right). Row hairlines use `--line` (`#2D3433` ink). The kicker badge pulls the live week number from `weekLabel` (e.g. renders `WK 22 / N` instead of a hardcoded `WK / N`) and the kicker text uses middle-dot separators with an en-dash date range (`WEEKEND MOVERS · WK 22 · MAY 22–28 2026`). Spec sections that were intentionally **not** implemented in this pass: S/M/L/XL logo-size toggle, adaptive disc luminance for light logos, monogram-initials fallback, and any switch off the existing same-origin `backed.fi` logo proxy. A second template — **The Overnight Tape** — lives at `/xstocks/earnings` (`app/xstocks/earnings/page.tsx` + `components/xstocks/earnings-builder.tsx` + `components/xstocks/earnings-builder.module.css`) and is purpose-built around the dark-window claim: this is the only place these names traded between 4 PM yesterday and 9:30 AM today. Every render anchors to a single global `SESSION` const at the top of the file (`{ state: "dark", windowLabel: "WED 4:00 PM ET → THU 9:30 AM ET", dateLabel: "MAY 28 → MAY 29 2026" }`) which surfaces as a literal `● NYSE DARK · XSTOCKS LIVE · WED 4:00 PM ET → THU 9:30 AM ET` `.sessionPill` between the kicker and headline — this is the product claim, not chrome. Two modes selected by the `Mode` control: **Spotlight** (single-print hero) and **Tape** (multi-row scoreboard, default when `FIXTURES.length > 1`, sized by a `Count` slider capped at `FIXTURES.length`). Both modes share the same hand-edited `FIXTURES: EarningsFixture[]` and are **auto-ranked divergence-first**: `sortByDivergenceFirst` puts beat-but-sold / miss-but-bought rows ahead of expected-direction rows (computed via `printScore` of the three verdicts vs `Math.sign(settlePct)`), then by `|settlePct|`. This means Spotlight auto-features the surprise of the day, not the biggest mover. The visual signature is the **arc**: `printPct` (initial post-print xStocks reaction) → `settlePct` (where xStocks sat just before TradFi open) → `openPct` (realized NYSE next-session open from prior close), each with its own time stamp. In Spotlight it renders as a three-box strip (`.arcStrip` grid `1fr 32px 1fr 32px 1fr`, settle box emphasized at 64 px and tracked-bg); in Tape it renders inline per row (`PRINT ▲ x% → SETTLE ▲ y% → OPEN ▲ z%`). The accountability loop is **The Call**: `callDeltaPp = openPct - settlePct`, with `isCallHit` true when `|delta| ≤ TRACK_RECORD.tolerancePp` (default 1 pp). Spotlight shows a full `.callRow` (`THE CALL / xStocks overnight settle → realized NYSE open / [✓ HIT  Δ +0.2pp]`); Tape ends each row with the same `.callPill` (gradient if hit, red if miss) inline. Divergent rows in Tape get a tinted gradient background (`[data-divergent="1"]`) and a `SURPRISE — BEAT BUT SOLD` / `MISS BUT BOUGHT` `.surpriseTag` next to the verdict pills. A toggleable `.trackRecord` band above the footer carries the running franchise number (`THE CALL · OVERNIGHT VS NYSE OPEN  28/30  within 1 pp · MAR – MAY 2026`); edit `TRACK_RECORD` to roll it. Each fixture's `whyLine` (one-liner editorial context like *"beat the print, sold the guide — concentration concerns"*) renders italic under the identity block (Spotlight) or under the arc (Tape) — the only piece that takes human judgment. Reuses the shared `weekend-movers-builder.module.css` for shell layout, `XS_GRAD`/`XS_X_PATH` brand mark, the `/api/xstocks/logo` proxy (all fixture tickers fit the existing ticker regex), and the data-URL pre-fetch pattern that fixes the `html-to-image` race. The Post-on-X text is built around the dark window in both modes: Spotlight emits `Between the bells. / When TradFi closed, $NVDA kept trading on xStocks. / Print ▲ x% / Settle ▲ y% / NYSE ▲ z% / The call: ✓ HIT — overnight off NYSE open by 0.2pp. / Track record: 28/30 within 1pp (MAR–MAY 2026). / When the market closes, price discovery doesn't. → xStocks`; Tape emits one `$TICKER print → settle → NYSE ✓ · surprise` line per print plus the per-night `Last night's call: N/M within 1pp` line and the cumulative track record. The `TemplateNav` switcher labels this route **Overnight Tape** to match the new framing. A `TemplateNav` component (`components/xstocks/template-nav.tsx`) renders at the top of both builders' control panels and cross-links `/xstocks` (Weekend Movers) and `/xstocks/earnings`, highlighting the active route via `usePathname`. A `Post on X` button next to `Download PNG` renders the same PNG, writes it to the OS clipboard via `navigator.clipboard.write([new ClipboardItem({ "image/png": blob })])`, and opens `https://x.com/intent/post?text=<encoded>` in a new tab with auto-generated copy in the fixed format `After-hours movers\n$TICKER ▲|▼ X.X% — why ... \n\nAll available to trade on-chain with xStocks.` The post lists *every* mover currently visible in the image (matches the `count` slider — top 1 shows 1 line, top 10 shows 10), not just the first 2. Cashtags are emitted without the trailing `x` (`HOODx` → `$HOOD`) so they render as recognizable underlying tickers on X. Percentages are signed via `▲`/`▼` arrows and rounded to 1 decimal. If the clipboard write is unsupported or denied, the PNG is auto-downloaded instead so the user can drag it into the X compose window; the inline hint under the button reflects which path was used.

  - Aggregated twice-daily RFQ quote-activity report (added `2026-05-14`, redesigned same day, trigger narrowed to zero-response streaks on `2026-05-18`). Fires twice per UTC day at `0 14 * * *` (≈10:00 AM ET under EDT / 9:00 AM ET under EST) and `0 21 * * *` (≈5:00 PM ET / 4:00 PM ET) — both schedules registered separately in `vercel.json` and the route detects which run via `Date.getUTCHours()` to pick its lookback window: the morning run scans the previous ≈17h (since the prior afternoon run) and the afternoon run scans the previous ≈7h (since the prior morning run). Any access outside those UTC hour bands (manual hits, debugging) defaults to a 7h lookback labelled `Ad-hoc`. Fetches `GET /api/rfq/quote-activity?days=2` once per run from the Solana indexer (`NEXT_PUBLIC_SOLANA_INDEXER_API_URL`, defaults to `https://indexer-solana-production.up.railway.app`), then for every `(asset, provider)` pair finds every ≥3-hour run of zero-response hours inside the lookback window via `findZeroResponseStreaksInWindow`. An hour counts as zero-response when `expected > 0 && success === 0`, regardless of why — both `all_failed` cycles and `missing_cycle` cycles trip it. The route no longer reads tone thresholds from `quoteVenueActivityTone`, so changing `bad`/`critical` cutoffs in `lib/rfq-quote-activity.ts` no longer affects what trips this cron. Flagged pairs collapse into a single aggregated Telegram message sent into the Kraken channel (`KRAKEN_TELEGRAM_BOT_TOKEN` + `KRAKEN_TELEGRAM_CHAT_ID`, same chat as `check-rfq-deviation`) under a single "🔴 No responses" section — there is no longer a critical-vs-bad severity split. Each line shows `ASSET · <code>VENUE</code>`. Runs with zero flagged pairs send nothing — silence is the all-clear signal. The JSON response reports a single `flagged` count instead of the prior `critical`/`bad` pair. Kill switch `QUOTE_ACTIVITY_ALERTS_ENABLED` defaults to off; with it off the route still runs and returns `preview: message` in its JSON response for inspection but does not post to Telegram. Because the cap is structural (≤2 sends per UTC day total, one per asset/venue mention per run), there is no per-asset or per-venue cooldown state — module-scoped maps from the earlier 15-min version were removed when the route was redesigned.

Above the campaign tabs sits `BirdsEyeZerogIncentiveEfficiencyChart` (`components/dashboard/birds-eye/birds-eye-zerog-incentive-efficiency-chart.tsx`): a multi-line chart, one line per incentivized pool, plotting **pool TVL ÷ the live campaign's allocated incentive** over time (the lookback-windowed efficiency "multiplier" — how much TVL each dollar of the campaign's incentive is holding). The denominator is **per-campaign / active-window**: each campaign's FULL allocated budget applies only on the days it is live (`start..end`); days with no live campaign get 0 (and are dropped), and overlapping campaigns on the same day are summed — so the line reflects the incentive allocated to whatever campaign is running that day, not a running total of every past campaign. For the Depth tab the probe also fetches the pool's primary-campaign recipients via `useMerklCampaignIncentives` and passes a `DepthConfig` (`{ walletSet, depthPct: 1 }`) into `useLiquidityHistoryByAddress` — an **opt-in extension** that, during the same backward event-replay, attaches `campaignDepthUsd` to each snapshot. Existing callers omit `DepthConfig` and pay nothing. **Depth is computed TVL-consistently**: for each wallet-set position, `amountsForPosition` is evaluated over the position's *overlap* with the ±1% tick band (`[max(tickLower, bandLow), min(tickUpper, bandHigh)]`) and valued with the same token USD prices as TVL. Because the band-overlap is a subset of the full range, **depth ≤ TVL is guaranteed** — do NOT use `calculateDepthFromRangeMap` here (it sums notional token0+token1 per tick and, summed bid+ask, overshoots TVL — for the oUSDT/USDC.e stablecoin pool it reported ~$156k depth against ~$80k TVL). Validated across all six 0G pools: depth/TVL ranges from ~0.9% (wide W0G/USDC.e) to ~97.5% (oUSDT/USDC.e — a stablecoin pair concentrates essentially all liquidity within ±1% of the peg). It reuses the shared `CampaignTvlRangeSelector` but passes a custom `options` list (`EFFICIENCY_RANGE_OPTIONS = [1, 7, 30, 45, 60, 90]`), so the multiplier charts additionally offer **1D/7D** short windows on top of the shared 30/45/60/90 presets — the selector is generic over the number type, so the Campaign-TVL/Katana/Monad consumers still infer `CampaignTvlRange` and are unaffected (this chart's `lookbackDays` state is widened to `number`).
