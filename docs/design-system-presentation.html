03 · Buttons

Variants × states

Four variants. Five states. This is the core interactive contract — primary for the one next step, secondary for alternatives, ghost for chrome, danger for irreversible actions.

Variant Default Hover Active Focus Disabled
Primary default .is-hover .is-active .is-focus disabled
Secondary default .is-hover .is-active .is-focus disabled
Ghost default .is-hover .is-active .is-focus disabled
Danger default .is-hover .is-active .is-focus disabled
Focus ring: 0 0 0 3px accent-soft + 0 0 0 4px border-focus. Never remove focus styles — keyboard users rely on them.

14 · Scalability

How the system grows without breaking

Blueprint scales by layers. New features compose existing tokens and primitives — they don’t invent a fifth blue or a one-off table skin.

01 · Tokens

Private + semantic

Color, type, space, radius, motion, status. Change once → whole product rebinds.

02 · Primitives

Button · Input · Pill · Card

Smallest shippable classes with forced states (hover / focus / disabled).

03 · Patterns

Panel · Table · KPI strip

Composed primitives: head/body/foot, sortable rows, metric cards.

04 · Products

Demo · Kraken · Birds-eye

Spaces reuse patterns. Theme scopes (e.g. Demo Blueprint) rebind tokens only.

→ → → →

What “increase” means here

Add without forking

  • New button? Use an existing variant or add one modifier.
  • New table? Same .bp-table + density + row states.
  • New space theme? Rebind semantics under a scope — don’t rewrite components.
  • New chart? Same panel shell + formatter contract.

Scale levers

  • Density: default → compact → dense
  • Emphasis: flat card → shadow card → bracketed panel
  • Meaning: neutral → ok / warn / bad / info
  • Theme: light canonical · dark after-hours · Demo showcase scope

Same primitives → larger surfaces

15 · Usage rules

Do / don’t

Do — one primary

Each view gets at most one primary button. Everything else is secondary or ghost.

Don’t — twin primaries

Two blue buttons side by side fight for attention and slow decisions.

Do — reuse table states

Hover / selected / disabled / density modifiers before inventing a new table component.

Don’t — one-off card skins

Status meaning goes through ok/warn/bad tokens — not a new hex per dashboard.

Do — compose panels

Head / body / foot + brackets. Charts plug into the shell; they don’t redefine chrome.

Don’t — status color for chrome

Green/red are for meaning. Decorative buttons stay accent / ink / ghost.
