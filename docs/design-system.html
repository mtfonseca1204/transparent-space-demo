Blueprint

A token-driven design system for Transparent Space — designed light-first, with a respectful dark mode for after-hours. Every decision below is tuned for legibility on a near-white canvas: deeper accents, crisp shadows that lift cards off the surface, and a chart palette saturated enough to read without screaming.

This is a working document. Every swatch, every component, and every chart on this page is rendered by the same CSS variables you would adopt in the codebase. Use the toggle in the top right to flip between light (canonical) and dark (secondary). Light is the source of truth.

01Principles

Six rules. They are short on purpose. When something feels off, it’s almost always because one of these is being violated.

01 / Light first
Every component is designed for the white canvas first. Dark is a careful re-binding, not a parallel universe.
02 / Information first
Type, color, and motion exist to make data legible. Decoration is the exception, not the default.
03 / Semantic over scalar
Components reference --accent, never --bp-blue-600. The scale is private.
04 / One source of truth
Tokens live in CSS variables. No hex inside components/. A lint rule enforces it.
05 / Quiet states matter
Loading, empty, error, and stale states are first-class. Designed, not afterthought.
06 / Numbers are tabular
Every numeric value uses tabular nums in IBM Plex Mono. Columns line up. Always.

02Why light mode is hard

Light mode is not “dark mode with the polarity flipped.” The problems are different, and so are the rules. This is the opinionated part — treat it as the spec for every decision below.

Cards need lift

In dark mode the void around a card defines its edge. On white, you have nothing — so cards need real shadow plus a subtle border to read as “a thing on a thing.”

Accent has to carry weight

A bright Tailwind blue-500 looks toy-ish on white. We use blue-600 / blue-700 for accent so links, primary buttons, and selected states feel intentional.

Status colors get deeper

Success / warning / danger all use the 600–700 step on white. The 500 step you’d use on dark is too pastel against #f6f8fc.

The canvas is not pure white

Pure white is glare. We use #f6f8fc for the page canvas and reserve #ffffff for cards — that one-step contrast is what makes a dashboard feel layered.

Borders are subtle, never invisible

Default borders are #dbe2ee — visible enough to define a card edge, quiet enough to disappear when you focus on data.

Chart colors must be saturated

A pastel line on white disappears. Categorical colors live in the 600–700 step (deep blue, deep teal, burnt amber) so a thin line still reads from across the room.

Do / don’t

Do — semantic tokens

background: var(--bg-surface);
color: var(--fg-primary);

Don’t — raw hex

background: #ffffff;
color: #0a1224;

Do — 600-step accent

On a white surface, blue-600 carries weight. Buttons and links feel intentional, not toy.

Don’t — 400/500 accent

Tailwind’s default blue-500 is for dark backgrounds. On white it looks pastel and indecisive.

Do — tabular nums everywhere

Use .font-num on every number. KPI columns line up.

Don’t — mix proportional

Inter on numbers makes a 6-card KPI strip wobble visibly. The user feels it as “cheap.”

Do — status colors for status

Use --status-ok / --status-bad only when the value means good or bad.

Don’t — status colors for series

Two unrelated lines should never be red and green. Use --cat-*.

Do — min 36 px touch targets

Tabs, FABs, and toggles. Affects touchpads and small windows too, not just mobile.

Don’t — py-1.5 text-[11px]

Looks fine on a 27″ monitor; impossible to hit on a laptop trackpad in a moving train.

10Accessibility floor

These are the non-negotiables. Hitting them does not make the product accessible — it makes it not embarrassing. Real accessibility is a separate audit; this is the floor.

  • Every interactive element has a visible focus ring: box-shadow: 0 0 0 3px var(--accent-soft), 0 0 0 4px var(--border-focus) on :focus-visible.
  • Active sidebar item carries aria-current="page".
  • Active tab carries aria-selected="true".
  • Touch targets are ≥ 36 px in their smallest dimension.
  • Body text is ≥ 14 px; never use the type scale below sm for paragraph copy.
  • Color contrast: every --fg-* token meets WCAG AA against the surface it’s rendered on. --fg-faint is for decoration only, never for content.
  • No information is conveyed by color alone. Status colors are paired with an icon, a label, or a shape.
  • Every chart has a text equivalent — either a visible legend or an aria-label on the SVG describing what it shows.

Lint rule

# Forbid raw hex in component files; allow it only in app/globals.css
- pattern: "#[0-9a-fA-F]{3,8}"
  paths:   ["components/**/*.{ts,tsx}"]
  message: "Use semantic tokens (var(--accent), bg-surface, etc.). Hex stays in globals.css."

12Adoption plan

This system is designed to be adopted incrementally. You should not freeze feature work to migrate. Suggested order:

  1. Land tokens. Drop the scale + semantic blocks into app/globals.css. Nothing breaks — the new vars are additive.
  2. Wire Tailwind @theme so utilities like bg-surface are available.
  3. Migrate primitives: button.tsx, input.tsx. These are the easiest and the most-used.
  4. Create new card primitives (Card, MetricCard, ChartCard) consuming only semantic tokens; keep the old ones in place until each consumer is moved.
  5. Build lib/format-utils.ts and lib/chart-theme.ts. Migrate two charts as the proof — price spread and TVL area.
  6. Add the lint rule. Now drift cannot re-enter even by accident.
  7. Migrate remaining charts one PR at a time. Each PR is small.
  8. Delete dead tokens. Once nothing references the old --bp-bg-* / --bp-text-* names, remove them.
The goal isn’t to make Transparent Space look different. Users should not notice anything visually changed on day one. They should notice, a month later, that the product feels tighter — that the dashboard feels solid, that the charts agree with each other, that nothing looks “off-brand.” That feeling is the design system doing its job.
